## Как делегировать (обязательно)
1. Сам НЕ выполняй работу специалистов, даже простую.
2. Для каждой части работы создай подзадачу через Paperclip API (скилл paperclip):
   POST $PAPERCLIP_API_URL/api/companies/$PAPERCLIP_COMPANY_ID/issues
   заголовки: Authorization: Bearer $PAPERCLIP_API_KEY, X-Paperclip-Run-Id: $PAPERCLIP_RUN_ID, Content-Type: application/json
   тело: {"title": "...", "description": "самодостаточное описание с критериями готовности", "parentId": "<id текущей задачи>", "assigneeAgentId": "<id исполнителя>", "status": "todo", "priority": "medium"}
   Назначение задачи сразу будит исполнителя.
3. Простую задачу отдавай одному исполнителю напрямую, не подключай лишних.
4. После создания подзадач оставь комментарий в своей задаче со списком подзадач и исполнителей, переведи свою задачу в статус blocked с blockedByIssueIds = id подзадач (или in_review) и заверши запуск. Не опрашивай исполнителей в цикле — тебя разбудят, когда подзадачи изменятся.
5. Когда кодовые подзадачи готовы — сам проверь результат (ревью), как раньше. Этот шаг обязателен: тестировщик его не заменяет и не отменяет.
6. Только после своего ревью создай подзадачу тестировщику (Тестировщик / Antigravity, `07635dfa-b839-431f-a957-c61a8b9f5790`) с `"blockedByIssueIds": ["<id кодовых подзадач>", ...]` и `"status": "blocked"`. Тестировщик проверяет, снимает скриншоты и возвращает результат тебе. Код он не чинит — при fail верни задачу инженеру.
7. Когда проверка тестировщика готова — закрой свою задачу (done) с кратким итогом (или верни в работу при fail).


## Зависимости подзадач (`blockedByIssueIds`)

Поле API: `blockedByIssueIds` — массив UUID задач, которые должны быть закрыты (`done`), прежде чем эта задача стартует. Передаётся в теле `POST $PAPERCLIP_API_URL/api/companies/$PAPERCLIP_COMPANY_ID/issues`. CLI `paperclipai issue create` этого поля не имеет — только HTTP API / скилл paperclip.

Пример: `{"title": "...", "description": "...", "parentId": "<id текущей задачи>", "assigneeAgentId": "<id>", "status": "blocked", "priority": "medium", "blockedByIssueIds": ["<uuid>", "..."]}`

- Если нужен Docs «до» (анализ) — его создаёт Мастер/Docs до кода; кодовые подзадачи тогда должны иметь `blockedByIssueIds` с id этой аналитической задачи.
- Код отдавай инженерам как обычно.
- Docs «после» (если создаёшь): `blockedByIssueIds` на кодовые подзадачи, `status`: `"blocked"`.
- Подзадачу тестировщику создавай только после своего ревью, с `blockedByIssueIds` на кодовые подзадачи.

## Правило сдачи: скриншоты

При приёмке результата проверяй, менялся ли интерфейс (UI):

- **UI менялся** (экраны, вёрстка, стили, визуальные состояния, анимации и т.п.) → в итоговом результате **обязательны скриншоты** финального UI.
- **UI не менялся** (только логика, тесты, рефакторинг без визуала, docs, ASO и т.п.) → скриншоты **не требуются**.

Не требуй скриншоты «на всякий случай», если визуал не менялся.
